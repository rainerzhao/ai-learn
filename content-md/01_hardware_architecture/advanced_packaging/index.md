# 先进封装与机柜成本拆解

AI 基础设施的底层瓶颈，已经不只是“买哪张 GPU”。从 IaaS 架构师视角看，GPU 集群的性能、成本和稳定性会被多层物理边界共同约束：芯片内部、封装内部、封装到主板、节点内部、机柜内部、机柜到集群网络。

这个专题把底层硬件拆成可以学习和复用的架构层：

| 层级 | 关键问题 | 对 AI 架构的影响 |
| --- | --- | --- |
| Die / Chiplet | 计算 die、I/O die、HBM 之间如何互连？ | 决定片内带宽、封装良率、单卡成本和能效。 |
| Package | 2.5D、3D、CoWoS、ABF、玻璃基板如何承载高密度互连？ | 决定 GPU/HBM 集成能力、SerDes 压力和下一代平台路线。 |
| Node | CPU、GPU、NIC、SSD、内存如何组织？ | 决定 NUMA、H2D/D2H、RDMA、存储路径和故障域。 |
| Rack | NVSwitch、ConnectX、供电、液冷、tray 如何集成？ | 决定机柜级成本、功耗、散热、部署密度和运维复杂度。 |
| Cluster | IB/RoCE、存储、调度、SLO 如何闭环？ | 决定训练扩展效率、推理容量、利用率和平台治理能力。 |

## 推荐阅读顺序

1. [2.5D、3D、玻璃基板与 ABF 封装互连对比](./01_2_5d_3d_abf_glass_substrate/)  
   先把材料、结构、互连和 I/O 协议拆开，避免把 ABF、玻璃基板、2.5D/3D 混成一个概念。

2. [SerDes 与封装链路预算](./02_serdes_package_interconnect/)  
   理解高速信号不是只由芯片 IP 决定，封装走线、过孔、焊点、PCB 和连接器共同消耗链路预算。

3. [NVIDIA NVL 机柜成本层级拆解](./03_nvidia_nvl_rack_cost_stack/)  
   用架构师视角拆解 GPU、HBM、NVSwitch、网络、供电、液冷和系统集成成本，避免只用单卡价格判断 AI 基建投入。

## 对 IaaS 架构师的迁移意义

- 过去看服务器 BOM，现在要看机柜级 BOM 和系统集成约束。
- 过去看 CPU、内存、网卡，现在要把 GPU、HBM、NVLink、NVSwitch、液冷纳入容量模型。
- 过去看网络吞吐，现在要区分训练通信、推理 KV Cache、存储加载和管理流量。
- 过去看采购成本，现在要同时看功耗、散热、良率、交付周期和运维可替换性。

## 知识更新规则

这类内容变化快，所有成本数字和路线判断都必须标注来源类型：

- **官方资料**：产品规格、架构白皮书、开发者博客。
- **论文/会议**：互连、封装、性能测试、架构评估。
- **媒体报道**：供应链、成本、交付节奏，需要标注发布时间。
- **分析师估算**：只能作为成本拆解线索，不能写成官方 BOM。

上线前需要重新确认来源日期，并完成本地 build 与浏览器检查。
