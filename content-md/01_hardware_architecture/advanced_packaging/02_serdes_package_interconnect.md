# SerDes 与封装链路预算

SerDes 是高速串行收发器，但它不是一个孤立 IP。它能跑多快、每 bit 能耗多低、误码率能否收敛，取决于整个物理通道。

## 1. SerDes 在系统里的真实路径

一个板级高速链路通常会经过：

```text
TX SerDes -> package substrate -> bump / ball -> PCB trace -> connector / cable -> PCB trace -> package -> RX SerDes
```

在先进封装内部，路径可能变成：

```text
die A PHY -> RDL / interposer / bridge -> micro-bump / hybrid bonding -> die B PHY
```

后者距离更短、带宽密度更高、每 bit 能耗更低，但制造、测试、热和良率压力更集中。

## 2. 链路预算关注什么

| 指标 | 含义 | 架构影响 |
| --- | --- | --- |
| 插入损耗 | 信号沿通道传播后的能量衰减 | 影响可达距离、速率和均衡复杂度。 |
| 回波损耗 | 阻抗不连续导致的反射 | 影响误码率和链路稳定性。 |
| 串扰 | 邻近通道相互干扰 | 影响高密度布线和并行链路数量。 |
| 抖动 | 时钟和边沿时间波动 | 影响采样窗口和恢复难度。 |
| 均衡能力 | CTLE、DFE、FFE 等补偿策略 | 决定 PHY 功耗、复杂度和可调空间。 |

## 3. 为什么先进封装会改变 SerDes 判断

传统服务器架构里，很多高速链路要跨主板、连接器、线缆和交换设备。AI 加速器把越来越多的互连压进封装内部或机柜内部，目标是减少距离和能耗。

但这不是简单“更短就更好”。封装内部互连也会带来新约束：

- 线宽线距更小，制造和缺陷控制更难。
- bump / micro-bump 间距更小，测试和返修更复杂。
- 封装面积更大，翘曲、供电和散热更难。
- D2D PHY 标准、封装工艺和 chiplet 生态需要一起成熟。

## 4. AI 架构师应该如何使用这个知识

在判断 GPU 互联、NIC 互联或下一代封装路线时，不要只问“带宽是多少”。更应该问：

1. 这条链路发生在封装内、节点内、机柜内，还是机柜间？
2. 它主要消耗芯片功耗、封装成本、PCB 成本，还是网络设备成本？
3. 它影响的是训练 all-reduce、推理 KV Cache、存储加载，还是管理面流量？
4. 它的故障表现是误码、降速、重训、作业失败，还是尾延迟抖动？

## 5. 一句话总结

SerDes 是芯片上的电路，但 SerDes 能力是系统级结果。封装、PCB、连接器、线缆、均衡和测试共同决定了高速互连的真实上限。
